# Proteus v0.4.0

Proteus v0.4.0 adds a source-evolving Codex CLI adapter and a local Visualize workspace,
and makes evaluator schedules, feedback, and episode phases configurable. It also fixes
the Codex tool-call counter, retains native failure diagnostics across recovery, and
repairs the release-smoke dependency setup.

## Highlights

### Source-evolving Codex CLI

- The pinned `openai/codex` Rust source is a measured `loop` surface alongside instructions,
  skills, notes, and tools. Fresh phases execute a frozen, read-only accepted snapshot while
  editing a separate candidate. The model-free boundary compiles tests and release binaries
  offline, probes startup, and publishes the validated binary pair by exact source hash.
- A failed candidate remains available for repair without changing the active runtime.
  Boundary validation receives no model credentials or model-phase mounts.
- One completed native patch counts as one tool call, even when it modifies many files.
  Every changed path and its surface remains in `ActionEvent.params["changes"]`; a patch
  spanning multiple surfaces has no single event-level surface.
- JSONL `error` and `turn.failed` diagnostics are retained, redacted, and carried into failed
  candidate records and resumed phase prompts. Diagnostics consume no tool-call budget.
- The release gate requires two live Codex episodes, a source edit in episode 1, matching
  binary activation in episode 2, and rejection of a planted compile error. Runtime source
  and publication identities are recorded in `traces/epNNN-runtime.json` outside snapshots.

Codex requires Docker and either an API key or an existing host Codex login. The source
environment is `linux/amd64` only; Arm hosts need emulation. Rust image builds and boundary
rebuilds can be expensive. See [the environment guide](../../environments/codex-src/README.md).

### Proteus Visualize

- `proteus visualize --out runs` opens a local workspace for recorded sweeps: evolution
  replay, candidate and accepted snapshot identities, named evaluator scores, structural
  and behavioral measurements, and comparisons across recorded runs.
- Viewing uses durable evidence and the existing measurement library, without importing
  the subject adapter, executing its code, or calling a model. Missing and errored scores
  remain missing; structural changes do not imply capability improvement.
- Launching requires `--allow-run-control` and an explicit action in the UI. The composer
  translates validated drafts into the existing CLI and always creates a fresh sweep.
  The default offline configuration now launches successfully; checkpoint reserves for
  `minimal` and `llm` are rejected during validation because they lack continuity.
- The service binds to loopback and checks Host, Origin, and a session token. Exports omit
  hidden scores by default, raw reasoning, tool parameters, and evaluator details.

See [the Visualize guide](../VISUALIZE.md) for launch controls, evidence limits, and exports.

### Evaluator controls and phase recovery

- Evaluator visibility, selection eligibility, and scheduling are independent. Run an
  evaluator at H0, every N episodes, or explicit checkpoints. Unavailable results have an
  explicit status and never become a valid selection baseline.
- Visible feedback retains the latest result with its source episode, age, candidate, and
  acceptance outcome. Skipped evaluation does not invent a fresh score. These policies are
  locked across resume.
- Supported adapters accept custom phase sequences and prompts. DSH can explicitly resume
  an interrupted phase from preserved candidate, session, and handoff evidence. Previous
  calls still count against the original budget; recovery neither refills the budget nor
  restores raw conversation history. An exclusive run lock prevents duplicate controllers.

See [evaluator controls](../BENCHMARKS.md#evaluator-roles-schedules-and-feedback) and
[the episode protocol](../EPISODE.md).

## Compatibility and migration

- **Finish v0.3.x sweeps with the version that created them.** The locked sweep condition
  includes the Proteus version; v0.4.0 refuses to join episodes from a different version.
  Start a new `--out` for v0.4.0. Visualize can read supported older durable records, but
  older native runs without normalized metadata retain missing behavioral measurements.
- Existing Codex progress and evaluator counters are not rewritten. Earlier multi-file
  patch counts may be inflated; start a new sweep when comparing native tool-call budgets.
- `checkpoint_turns` still requires an explicit phase allocation, announced budget, and
  a harness with native or framework continuity. The viewer's default reserve is now zero.
- Sparse selection does not certify intermediate snapshots. Use every-episode selection
  when each accepted candidate must have benchmark evidence.
- The release gate installs DSH's optional log-decoding dependency before running recovery
  tests. Codex is a required release job; missing authentication fails the gate.
- Pinned Pi images recover model values from the matching official npm package and check
  them with Pi's validator, avoiding catalog drift when an upstream provider disappears.
- PyPI publishing requires a successful smoke run triggered by the exact release tag and
  commit, with all six required jobs successful. A green older run or skipped Codex job
  cannot authorize an upload.

## Install

```bash
python -m pip install --upgrade proteus-evolve==0.4.0
```

Proteus remains a research preview and requires Python 3.10+. Release environments pin DSH
`dsh-v0.1.0-rc.7`, Pi `v0.84.2`, and Codex commit
`a7b86b6201d35200280e3d24ca5ebccd8122d6ca`. The upstream canary remains advisory.
